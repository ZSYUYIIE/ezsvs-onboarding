# 第一关大堂闸机穿模修复

版本 `0.4.3-web.2`，2026-11-18。基于线上 `0.4.3-web.1` 的 Unity 源码制作。

## 问题与修复

线上大堂使用的闸机是一个合并模型，整个模型的碰撞被 `Passable` 关闭。角色和相机可以穿过机身，画面中的玻璃挡板仍横在通道内。原始通道净宽为 0.6 米，与角色碰撞体直径相同。

本次为三条闸机通道分别设置机身碰撞，将闸机横向宽度从 1 米扩至 1.4 米，玻璃挡板改为沿通道侧边打开，挡板保留实体碰撞。考虑挡板厚度后的通道净宽约 0.8 米。两侧固定护栏随闸机组宽度对齐。玻璃处于固定打开状态。

## 验证

原版在 30 项专项检查中有 12 项失败，覆盖机身导航、身体碰撞与相机阻挡。修复版 30 项全部通过，包括三条通道的双向行走、六处机身碰撞、相机阻挡和固定玻璃护栏。另有 17 项 JavaScript 工具测试、6 项打包测试通过。

桌面浏览器英文课程 207 项、中文课程 202 项全部通过，移动 ETC2 构建的英文课程 207 项通过。正常行走测试中，撞向机身时停在 z = −13.015 米，闸机前沿位于 z = −12.7 米。移动构建在 844×390 的触屏模拟中，通过摇杆从 z = −13.5 米行走至 z = −8.918 米，成功穿过打开的通道，应用错误记录为空。

源码修改位于 `Assets/GuardiansDemo/GuardiansRooms.cs`，版本位于 `Assets/Editor/WebBuild.cs`，专项回归位于 `Assets/Editor/LobbyGateChecks.cs`。使用 Unity 6000.3.22f1，打开原源码工程并覆盖源文件后，可执行以下检查。

```powershell
Unity.exe -batchmode -nographics -quit -projectPath <工程路径> -executeMethod EZSVS.LobbyHotfix.Checks.Validate -logFile <日志路径>
```

桌面 DXT 与移动 ETC2 由同一源码构建。浏览器测试过程静音。手机真机验证仍需在实际 Android/iOS 设备上完成。
