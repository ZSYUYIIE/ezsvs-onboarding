# 课程楼层限制、相机穿模与无关场景精简

版本 `0.4.4-web.1`，2026-11-26。基于 `0.4.3-web.3` 源码，网页加载页沿用 2026-11-25 已上线的版本（含背景音乐替换）。

## 楼层按课程开放

此前第一关可从大堂楼梯直接走上二楼进入机房，绕过关闭的闸机。楼梯在半层平台直接切换楼层，没有检查课程进度。

现在课程进行中，楼梯、电梯和门只通向当前关卡所在楼层。走上未开放的楼梯时，角色停在本层楼梯口，并提示“某楼层还没对你开放。先完成当前任务，课程会带你过去。”（英文界面同步）。关卡之间仍由课程自动切换楼层，不影响推进。自由探索、测试和抓图模式不受限制。

源码：`GuardiansOnboarding.cs`（`CourseBlocks`）、`GuardiansGame.cs`（`StairClosed`、门的跳转）、`GuardiansUI.cs`（电梯菜单）。

## 相机穿模

新增编辑器审计 `EZSVS.ClipAudit.Audit.Run`（`Assets/Editor/ClipAudit.cs`，结果写入 `Logs/clip-audit.json`）。在课程四个场景按 1.2 米（室外 3 米）网格取可行走点，每点 8 个方向 × 2 个俯角 × 2 个距离，用游戏自身的相机逻辑求相机位置，再检查相机是否落进有画面但没有碰撞体的几何体内。

原因：桥架、线缆、风管、母线槽、吊顶和楼梯间墙体为了让角色从下面或旁边走过，没有碰撞体，相机因此直接穿过。

处理：
- `MeshKit` 为腰部以上（≥0.9 米）不透明、非碰撞的盒体和管道生成“仅相机”碰撞体（第 30 层）。角色身体、导航不使用该层。
- 相机先降到头顶设施下方，再按原距离摆放，避免频繁拉近（`GuardianCameraCollision.UnderOverhead`）。
- 楼梯间围墙原碰撞体只有 1.2 米高，补上整面墙的相机碰撞。

| 场景 | 修改前相机落入几何体 | 修改后 |
|---|---:|---:|
| 园区（序） | 347 | 76 |
| 一层大堂 | 161 | 7 |
| 二层 B 区机房 | 1431 | 118 |
| 三层办公室 | 91 | 0 |

剩余主要为玩家到不了的马路车辆，以及二层贴近吊顶的细吊杆。

## 模型穿模

审计同时检查课程人物站位：
- 第一关保安秦站进前台桌内：移到桌后（z −13.85）。
- 第一关外包人员站在闸机玻璃里：移到闸机通道内、玻璃前（−23.8, −12.35）。

站位均保留第一关“借卡”步骤所需的 0.9 米通行宽度。

## 无关场景精简

网页版（`GuardiansSites.CourseOnly`）中，一层闸机后的柴油发电机房和冷站只保留墙体与门洞。第一关不会进入也看不到这两间（隔两道墙）。一层物体 1622 → 755，渲染器 525 → 411，三角面 22.2 万 → 13.7 万，点光源 80 → 64。

## 其他

- 编辑器中 `GetComponent<MeshFilter>()?.` 遇到文字标识会抛出异常（编辑器的假 null），改用 `TryGetComponent`。播放器行为不变。
- 本机 GI 缓存默认目录是指向 `D:\DevCache\Unity\GiCache` 的目录链接，Unity 不接受，构建时会在 BuildPlayer 循环报错。`EZSVS.Editor.GiCachePrefs.UseDevCache` 把 GI 缓存偏好直接设为该目录。
- 构建使用 `Workspace/onboarding-toolchain` 中的 Unity 6000.3.22f1。
